01 Co-op / LLM data pipeline LaReg An LLM pipeline that turns energy-project dockets into structured records where every field cites its source. Built with AI agents working in parallel. run
  1. $ run lareg --agents 4
  2. retrieval pull filings from Postgres and S3
  3. ocr read scanned pages with Textract
  4. extract fill the record with Gemini
  5. guards check ownership against the source
  6. merged. expanding

The problem

State utility commissions keep dockets, the case files for proposed energy projects like solar farms and transmission lines. Companies file PDFs into them, many of them scanned, and LaReg sells the structured data buried inside. The old pipeline fed the model a fixed handful of PDFs per docket, which often meant half a filing.

What I built

Given a docket, the pipeline finds its filings in Postgres, pulls the PDFs from S3, and runs OCR with AWS Textract on scanned pages. A filing goes to the model whole or not at all, inside a token budget, so Gemini never sees a fragment of one. Gemini fills a structured record from a grounded prompt, and every field carries the file and page it came from. An unparseable response counts as a failure, never as a silent blank.

The hard part

Ownership. The model kept naming the applicant as the owner, so I added deterministic checks after extraction that blank the answer unless the cited text actually says who owns the project. Separately, I retrained the BERT classifier that sorts projects into subcategories, using recent data to fix classes that had too few examples.

How the work got done

I ran several AI coding agents at once, each on its own piece of the pipeline, inside guardrails I set: read-only access to production data, outputs could only be added to and never overwritten, and every claim had to cite a docket number. My job was scoping the tasks, reviewing what came back, and deciding what shipped.

02 Project / Full stack AutoPod Type a topic, get back a finished podcast episode. Claude researches and writes it, Cartesia voices it. run
  1. $ run autopod "why bridges sway"
  2. validate is the topic safe and doable
  3. research Claude gathers structured notes
  4. script Claude writes it for multiple hosts
  5. voice Cartesia reads every line
  6. save one MP3 to Supabase
  7. episode ready. expanding

What it does

You type a topic, pick a style and a length, and get back a podcast episode you can play. Next.js and React on the front, Node and Express on the back, Supabase for accounts and storage.

How a request flows

Claude first checks that the topic is safe and doable, before any account work happens. Then the request passes a Supabase login check and runs through three stages: Claude researches the topic into structured notes, Claude turns the notes into a script where every line has a speaker and an emotion, and each line goes to Cartesia's text-to-speech API. The audio chunks get stitched into one MP3, uploaded to Supabase Storage, and the episode details go into the database so your library is there next time.

The decision I'd defend

Every Claude call answers in a fixed JSON schema. The model has to respond in a shape the code already expects, so a weird response can't break the pipeline halfway through an episode.

03 Research / Computer vision Parking lot occupancy Estimates how full mall parking lots are from satellite imagery, as a signal of economic activity. run
  1. $ run occupancy --country US
  2. sites pull malls from OpenStreetMap
  3. sample same weekday, every month
  4. frames nearest clear satellite pass
  5. read vision model fills the schema
  6. pivot mall × date matrix
  7. matrix ready. expanding

What it does

Give it a list of malls, typed in or pulled from OpenStreetMap, and it builds a mall-by-date table of how full each parking lot was. For every mall and date it finds the nearest clear satellite image, and a vision model reads the occupancy into a strict schema: a percentage, a confidence, and whether clouds hid the lot. Pydantic validates every read, and pandas pivots them into the final matrix.

Why the same weekday

Parking depends far more on the day of the week than on the date. A Saturday isn't comparable to a Tuesday. So it samples the first and third Thursday of every month, and when no clear image exists it searches in whole weeks so the substitute stays on a Thursday.

Cost and honesty

Every satellite frame is a paid order, so it buys the cheapest image that's sharp enough to judge fullness, refuses anything over a price cap, and caches every result so a rerun never pays twice. A missing image is recorded as missing, never as an empty lot. Going from a few malls to hundreds is a data change, not a code change.

04 Product / Claude Code Outbound sales kit A Claude Code kit that runs cold outreach end to end, with a person approving every email. run
  1. $ run outbound --daily
  2. leads find and score new leads
  3. draft write each email in your voice
  4. approve hold for a human yes
  5. send on schedule, under daily caps
  6. triage sort the replies
  7. batch done. expanding

What it does

It finds leads, scores them, and drafts each email in the sender's own voice. Nothing sends until a person approves it. Approved emails go out on a fixed follow-up schedule with daily send caps, so a mailbox never looks like spam, and replies get triaged into a weekly report.

How it's built

Each job is its own Claude Code skill: onboarding, the daily batch, the approval sweep, follow-ups, reply triage, and the weekly report. The skills call Python scripts for the parts that should be deterministic, and a test suite covers those scripts.

Where it is now

It's being packaged and sold as a product, with a done-for-you setup for people who'd rather not install it themselves.

05 Personal system / Tooling Second brain A plain-text vault of my notes and decisions that Claude Code reads, maintains, and audits on its own. run

  2. capture new note into the inbox
  3. route split it across the right files

What it is

My notes, decisions, and projects live in a plain-text Obsidian vault that Claude Code can read and maintain. I wrote custom skills to capture new notes, route them to the right place, and trace how my thinking on something has changed over time.

What keeps it in order

Hooks lint every edit as it happens and log every commit to a changelog, and each commit is pushed to a private GitHub backup automatically. A weekly cloud job audits the whole vault for broken links and stale notes, even when my laptop is off.
